> F-6「施設予約自動化」で使う AWS の設定手順です。  
> AWSを初めて使う方でも迷わないよう、画面の操作手順を細かく書いています。  
> 所要時間の目安：**30〜60分**

## 事前に用意するもの

- メールアドレス（Gmail など）
- クレジットカード（登録は必要ですが、今回の用途では**無料枠内**に収まります）
- 電話番号（SMS 認証用）

## ステップ 1：AWS アカウントを作る

1. ブラウザで https://aws.amazon.com/jp/ を開く
2. 右上の「**AWS アカウントを作成**」をクリック
3. メールアドレス・パスワード・アカウント名を入力して「続行」
   - アカウント名は何でも OK（例：`yoshiki-badminton`）
4. 連絡先情報の入力（「個人」を選択し、氏名・電話番号・住所を入力）
5. クレジットカード情報を入力
   - 登録するだけで請求はされません（無料枠確認のための本人確認）
6. 電話番号認証（SMS または自動音声で 4 桁のコードが届く）
7. アカウントプランの選択画面が出たら「**有料プランを選択してください**」を選ぶ
   - 「無料（6ヶ月間）」を選ぶと**6ヶ月後にアカウントが自動閉鎖**されるため、長期運用のボットには不向きです
   - 「有料」を選んでもLambdaは月100万回まで永久無料なので、実際の請求はほぼ0円です
8. サポートプランは「**ベーシックサポート — 無料**」を選択
9. 「AWS マネジメントコンソールへ進む」をクリック

> **補足：** クレジットカードを登録しても、Lambda + API Gateway の今回の使い方では無料枠を超えません（Lambda は月 100 万回まで無料）。

## ステップ 2：セキュリティの初期設定（MFA）

AWS は「なりすまし不正利用」の被害が多いサービスです。ログイン時に 2 段階認証（MFA）を設定しておきます。

1. コンソール右上のアカウント名 → 「**セキュリティ認証情報**」をクリック
2. 「多要素認証 (MFA)」セクションの「**MFA を割り当てる**」をクリック
3. 「認証アプリ」を選択して「次へ」
4. スマホに **Google Authenticator**（無料アプリ）をインストール
5. 表示された QR コードをアプリでスキャン → 6 桁のコードを 2 回入力
6. 「MFA を追加」をクリックして完了

---

## ステップ 3：Lambda 関数を作る

1. コンソール上部の検索欄に「**Lambda**」と入力してクリック
2. 「**関数を作成**」をクリック
3. 以下のとおり入力して「関数の作成」をクリック

| 項目 | 設定値 |
|:--|:--|
| 関数名 | `badminton-reserve` |
| ランタイム | `Node.js 20.x` |
| アーキテクチャ | `x86_64`（デフォルト） |
| 実行ロール | 「基本的な Lambda アクセス権限で新しいロールを作成」（デフォルト） |

4. 関数が作成されたら「**設定**」タブ → 「**一般設定**」を開く
5. 「**タイムアウト**」を `3秒` → `30秒` に変更して「保存」
   - 予約フォームの送信に時間がかかるため、デフォルトの 3 秒だと途中で止まってしまいます

## ステップ 4：コードをアップロードする

> **ここでは、実装エージェントが作成した `lambda/` フォルダのコードを使います。**  
> エージェントの実装が終わってから進めてください。

### 4-1. Node.js をパソコンにインストールする（まだの場合）

https://nodejs.org/ja/ から **LTS 版**をダウンロードしてインストール。

### 4-2. 依存パッケージをインストールして zip ファイルを作る

PowerShell（またはコマンドプロンプト）を開いて以下を実行：

```powershell
cd C:\Users\Yoshiki\projects\gas-badminton-scheduler\lambda
npm install
```

次に、`lambda` フォルダ全体を zip に固める：

```powershell
Compress-Archive -Path * -DestinationPath ..\lambda.zip -Force
```

> `lambda.zip` が `gas-badminton-scheduler` フォルダ直下に作られます。

### 4-3. zip を Lambda にアップロードする

1. Lambda コンソールの「**コード**」タブを開く
2. 「**アップロード元**」→「**.zip ファイル**」をクリック
3. 先ほど作った `lambda.zip` を選択してアップロード
4. 「**保存**」をクリック

### 4-4. 環境変数を登録する

予約フォームにログインするための情報を登録します（コードに直書きしないためのセキュリティ対策）。

1. 「**設定**」タブ → 「**環境変数**」→「**編集**」をクリック
2. 「環境変数を追加」で以下を登録：

| キー | 値 |
|:--|:--|
| `RESERVE_API_TOKEN` | 自分で決めた秘密の文字列（英数字32文字以上推奨。例：`openssl rand -hex 16` で生成） |

> **RESERVE_API_TOKEN について：** GAS と Lambda の間の合言葉です。GAS 側の ScriptProperties にも同じ値を登録します（ステップ7）。ランダムな文字列なら何でも OK ですが、メモしておいてください。

> **バド卓ねっとはログイン不要です：** 氏名・電話番号・メールアドレスだけで予約できる仕様のため、ログイン ID やパスワードの登録は不要です。

3. 「保存」をクリック

## ステップ 5：API Gateway を設定する

Lambda は「直接インターネットから呼べない」ため、**API Gateway**（外から叩ける URL の入り口）を前に置きます。

1. Lambda 関数のページ上部「**トリガーを追加**」をクリック
2. 「**API Gateway**」を選択
3. 以下のとおり設定して「追加」をクリック：

| 項目 | 設定値 |
|:--|:--|
| API タイプ | `HTTP API` |
| セキュリティ | `オープン`（後でAPIキーを追加します） |

4. 作成後、「**API エンドポイント**」の URL が表示されるのでメモしておく
   - 形式：`https://xxxxxxxxxx.execute-api.ap-northeast-1.amazonaws.com/default/badminton-reserve`

> **リージョン（地域）について：** 東京リージョン（ap-northeast-1）で作ることをお勧めします。Lambda を最初に作る際、コンソール右上のリージョン選択が「**東京**」になっているか確認してください。

## ステップ 5-2：EventBridge ルールを設定する（コールドスタート対策）

> **このステップでやること（速度最適化）：**  
> 体育館の予約開始時刻（7:00）は争奪戦です。Lambda は起動直後（コールドスタート）に処理が少し遅くなる性質があります。  
> **EventBridge**（AWSのタイマー機能）を使って、**毎朝 6:59** に「準備運動（warmup）」を実行させておきます。  
> これで 7:00 の予約処理を最速で始められます。

> **warmup の中身：** バド卓ねっとのページに軽い確認リクエスト（HEAD リクエスト）を送るだけです。ログインや予約は行いません。

### 設定手順

1. Lambda 関数のページ上部「**トリガーを追加**」をクリック
2. トリガーの種類として「**EventBridge（CloudWatch Events）**」を選択

3. 「**新規ルールを作成**」を選んで、以下のとおり入力：

| 項目 | 設定値 |
|:--|:--|
| ルール名 | `badminton-warmup` |
| ルールの説明（任意） | 毎朝6:59にコンテナを温めて予約速度を上げる |
| ルールタイプ | 「**スケジュール式**」を選択 |
| スケジュール式 | `cron(59 21 * * ? *)` |

> **スケジュール式の読み方：** AWSのタイマーは「UTC（世界標準時）」で設定します。  
> 日本時間（JST）は UTC + 9 時間なので、日本時間 6:59 = UTC 21:59 です。  
> `cron(59 21 * * ? *)` は「毎日 21:59 UTC（= 日本時間 6:59）に実行」という意味です。

4. 「**ターゲット入力の設定**」で「**定数 (JSON テキスト)**」を選択し、以下を入力：

```json
{"action": "warmup"}
```

> **このデータの意味：** Lambda に「これは準備運動（warmup）だよ」と伝えるための合言葉です。  
> これを受け取った Lambda はバド卓ねっとのページに軽い確認リクエストを送り、次の予約処理をすぐ始められる状態にします。

5. 「**追加**」ボタンを押して完了

### 動いているか確認する方法

設定の翌朝、以下の手順で確認できます：

1. AWSコンソールで「**CloudWatch**」を検索して開く
2. 左メニューの「**ロググループ**」をクリック
3. `/aws/lambda/badminton-reserve` のログを開く
4. 翌朝 6:59〜7:00 ごろのログに以下が表示されていれば成功です：

```
[INFO] warmup: コンテナ準備完了
```

> **表示されなかった場合：** `badminton-warmup` ルールが正しく設定されているか、Lambda 関数名が `badminton-reserve` になっているかを確認してください。

## ステップ 6：動作テストをする

### 6-1. Lambda コンソールのテスト機能で確認（scan）

まず、指定日に空いているコートが取得できるか確認します。

1. Lambda 関数の「**テスト**」タブを開く
2. 「新しいイベントを作成」を選択して、以下の JSON を貼り付ける：

```json
{
  "action": "scan",
  "date": "2026-06-01",
  "startTime": "13:00",
  "courseGroupIds": [14881, 14882]
}
```

> **courseGroupIds について：** 鳥屋野総合体育館のコースグループ ID です。GAS の ScriptProperties（`TOYA_COURSE_GROUP_IDS`）に登録した値を使います。最新の ID は実際の予約サイトで確認してください。

3. 「**テスト**」をクリック
4. 実行結果に `"success": true` と `"courts": [...]` が返れば OK です

### 6-2. API Gateway 経由でテストする

PowerShell で以下を実行（URL は ステップ 5 でメモしたものに置き換える）：

```powershell
$body = '{"action":"scan","date":"2026-06-01","startTime":"13:00","courseGroupIds":[14881,14882]}'
$headers = @{ 'X-Api-Token' = 'ステップ4-4で登録したRESERVE_API_TOKENの値' }
Invoke-RestMethod -Uri "https://xxxxxxxxxx.execute-api.ap-northeast-1.amazonaws.com/default/badminton-reserve" -Method POST -Body $body -ContentType "application/json" -Headers $headers
```

`success: true` と `courts` の一覧が表示されれば成功です。  
`401` エラーが出た場合は `X-Api-Token` の値が Lambda の環境変数と一致しているか確認してください。

## ステップ 7：GAS に URL を登録する

API Gateway のエンドポイント URL を GAS の設定に登録します。

1. GAS エディタを開く（clasp を使っている場合は、ブラウザで Apps Script を開く）
2. 「**プロジェクトの設定**」→「**スクリプト プロパティ**」に以下を追加：

| プロパティ名 | 値 |
|:--|:--|
| `AWS_RESERVE_URL` | ステップ 5 でメモした API Gateway の URL |
| `RESERVE_NAME` | 予約フォームに入力する代表者の氏名（あなたの名前） |
| `RESERVE_TEL` | 予約フォームに入力する電話番号 |
| `RESERVE_EMAIL` | 予約フォームに入力するメールアドレス |
| `RESERVE_API_TOKEN` | ステップ 4-4 で Lambda に登録したものと**同じ**トークン文字列 |
| `RESERVE_ENABLED` | `false`（実機テストが完了したら `true` に変える） |

3. 「スクリプト プロパティを保存」をクリック

## よくある質問

**Q. クレジットカードを登録したら勝手に請求されませんか？**  
A. 今回の使い方（月数回の予約）では無料枠を絶対に超えません。ただし念のため、AWSコンソールの「**請求とコスト管理**」→「**請求書**」で確認できます。

**Q. リージョン（地域）はどこを選べばいいですか？**  
A. 「**アジアパシフィック（東京）ap-northeast-1**」を選んでください。コンソール右上で確認・変更できます。

**Q. 途中でエラーになったらどうすればいいですか？**  
A. エラーメッセージをそのままチャットに貼り付けてください。一緒に確認します。

**Q. EventBridge の cron 式が複雑でよくわかりません。**  
A. `cron(分 時 日 月 曜日 年)` という形式で、今回の `cron(59 21 * * ? *)` は「毎日（`*`）21:59 UTC に実行」という意味です。`?` は「曜日は指定しない」という意味で、日本時間では 6:59 になります。
